Public account fixtures use [BIP340 test vector 0](https://github.com/bitcoin/bips/blob/master/bip-0340/test-vectors.csv), with secret scalar 3 and its published x-only public key. Public account and SHA tree/purchase/marker literals were computed separately with Python `hashlib` using the pinned LEZ domain and the research encodings. Private account literals come from the pinned LEZ helpers and their test vectors.

Poseidon literals were computed with a Python port of the pinned [reference algorithm](https://github.com/iden3/circomlibjs/blob/48b3ab37013c5ed21e9ff8a80a5b010795c97094/src/poseidon_reference.js) and [constants](https://github.com/iden3/circomlibjs/blob/48b3ab37013c5ed21e9ff8a80a5b010795c97094/src/poseidon_constants.json), outside this package. The reference was checked against the upstream `[1,2]` and `[1,2,3,4]` examples and a published full-byte example. The constants file SHA-256 is `354f31bbed9d9a8b884d8f2181e339cb425b6e3e4cc7240bd3dd22f0070f3f2c`. Tests retain leaf, padding, parent, root and full-width blinder outputs. They do not use `eligibility-core` or `light-poseidon` to calculate the expected values.

## Local prover provenance

With the documented PATH and no server override, the inspected `r0vm` 3.0.5 executable has SHA-256 `e57ef8a01d97d1b87ca7f1fb7ab55eb636d478d7e5a8e498bbe985120c3e81f9`. Its bytes match the member in the [official macOS ARM64 release archive](https://github.com/risc0/risc0/releases/download/v3.0.5/cargo-risczero-aarch64-apple-darwin.tgz). The archive SHA-256 is `0f676055ad88d7ede06beaec3b7f850413e091db08bb7cf9969a78d9ad168562`, matching the [release API digest](https://api.github.com/repos/risc0/risc0/releases/tags/v3.0.5).

The [published release build](https://github.com/risc0/risc0/blob/8eb06ab020a92dc5b63ba6dd0836d432aba6d890/.github/workflows/release.yml) uses `cargo build -p cargo-risczero --release --locked`. The [server manifest](https://github.com/risc0/risc0/blob/8eb06ab020a92dc5b63ba6dd0836d432aba6d890/risc0/r0vm/Cargo.toml) enables `prove`; its [feature definition](https://github.com/risc0/risc0/blob/8eb06ab020a92dc5b63ba6dd0836d432aba6d890/risc0/zkvm/Cargo.toml) does not enable `circuit_debug` or `witgen_debug`. No independent external-server feature manifest or effective compiler-setting record was verified. The linked release run reports failure with no available step results; its failure cause was not established. Binary identity and the published recipe are provenance evidence, not confidentiality certification or evidence about executables used in earlier runs.

The native experiment calls the pinned LEZ [`execute_and_prove`](https://github.com/logos-blockchain/logos-execution-zone/blob/a58fbce2ff48c58b7bb5001b1a27e64b9596ee3a/lee/state_machine/src/privacy_preserving_transaction/circuit.rs) driver. It does not copy that driver or enable in-process proving. Each native attempt checks the local executable against the SHA-256 above and passes its resolved path to a dedicated IPC worker. The worker receives the synthetic trial over stdin. Only the final outer receipt and aggregate measurements return to the parent; inner program journals contain the witness and stay private.

Pinned `lee` loads a cached outer privacy-circuit binary and derives its trusted image ID from that artifact: `ab86d257c5e0b8a8f6390b35500c37ca24fa57aa7a06bda330753cf36ad6a249`. The native host verifies against this fixed local ID. The [artifact helper](https://github.com/logos-blockchain/logos-execution-zone/blob/a58fbce2ff48c58b7bb5001b1a27e64b9596ee3a/build_utils/src/lib.rs) does not rebuild the circuit. This experiment did not verify a source-to-binary comparison or an independent expected outer image for the pinned revision. No mismatch was found, but source pinning and application guest builds do not establish outer-circuit provenance.

The native driver has no segment-path argument. Inspected SDK default segment storage uses `tempfile::tempdir()` and `std::env::temp_dir()`; the IPC process inherits its environment and file-creation mask. The runner therefore uses child-only `TMPDIR` beneath an owner-only `0700` parent, `umask 077` and disabled core dumps. It samples subtree permissions, file counts, sizes and process-group RSS every two seconds, then removes the subtree. These observations cover sampled files beneath that parent. They do not establish that every transitive library writes only there or that no short-lived write escaped sampling. Deletion is not secure erasure; same-user access and parent crashes remain risks.

The direct public guest checker uses SDK receipt verification with verifier-owned parameters and an image pin. It was written here from the SDK interface. DistributionX's older LEZ pin, Ed25519 account binding, salt-based marker and journal-as-receipt client stub were not adopted. The [research report](../../docs/research/lbp-eligibility-proof.md) states what was tested and what remains open.
