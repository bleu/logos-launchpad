# Small eligibility-proof experiment

Semaphore proof generation was fast in the small local test, but the tested Rust verifier did not finish within LEZ's charged public action budget. This is not a selected allowlist design or evidence that all Groth16 verifiers fail on LEZ.

The 2026-11-09 amendment to [ADR 0021](../../docs/adr/0021-modes-and-open-limits.md) extends allowlists to all pricing engines and removes the collateral cap and one-purchase allowance. References to those requirements below describe the earlier scope; the measurements do not validate the revised private-account design.

## Results

On 2026-11-09, an Apple M3 Pro with 11 logical CPUs and 18 GiB RAM ran Node 24.22.1 on macOS 27.0.1. One genuine depth-17 proof used one random synthetic Semaphore identity and two dummy commitment leaves:

- Local SDK `generateProof`: 0.601017 seconds, including its artifact loading, witness calculation and proving.
- Whole child process: 0.899084 seconds, including setup, key export and verification.
- Child peak RSS: 587,218,944 bytes, covering the whole worker rather than proving alone.
- Official SDK verification, separate snarkjs verification and Rust host verification passed.
- Node tests passed 4/4; Rust host tests passed 13/13. Rust formatting and strict host lint passed.
- Signed local LEZ execution failed with `OutOfGas { budget: 10000000 }`. It did not finish verification. The gate test remains failing; it was not changed to expect rejection.

This was a fresh Node process with artifacts already on disk. The OS file cache was not cleared. No separate artifact-loading or witness-only measurement was made. Depth 17 can represent at least 100,000 leaves, but this test did not construct that group or measure that capacity. The failed execution gate stopped the 100,000-member and repeat benchmark stages. No higher-budget retry, outer privacy proof, block submission or funded trade was run.

The baseline parsed and checked its fixed key and prepared the pairing key at runtime. After updating the branch to main `f1eea8a3b06ac31dc8e93d78df81675f4d20da00` on the same day, the unchanged baseline failed the same gate again. The platform pins were unchanged.

The follow-up moves fixed-key validation and preparation into `rust/verifier/build.rs`. It embeds the uncompressed canonical `PreparedVerifyingKey`, including the fixed alpha/beta pairing and prepared negative gamma/delta points. Runtime decoding skips repeated validation only for these immutable build-generated bytes, checks full byte consumption and five input-coefficient points, and keeps all checks on untrusted proofs and public inputs. The proof and official key fixtures are unchanged.

The prepared-key verifier also failed with `OutOfGas { budget: 10000000 }`; the local execution attempt took 0.186386 seconds before failure. This is execution time, not proof-generation time. No completed total cycle count or cycle saving was measured. The unchanged gate remains failing. Work stopped without another optimization, a higher budget, or the 100,000-member benchmark. Follow-up checks passed all 13 Rust host tests, all four Node tests, formatting and strict host lint. Node tests still emit a listener-count warning.

## Reproduce

Run from the repository root. Exact package versions, artifact origins, hashes and public-signal order are in [sources.json](fixtures/sources.json). Semaphore SDK 4.14.5 intentionally selects circuit artifacts 4.13.0. The Rust checker uses Arkworks 0.5.0. LEZ is pinned to `578ce58a71b79c49d48e97e51c520bf71f0252d9`, RISC0 to 3.0.5 and the host build wrapper to zkOS 2.2.2, matching `verify/actor-tools.env`. The guest lock resolves the transitive `risc0-zkos-v1compat` dependency to 2.2.3.

```sh
npm ci --prefix packages/eligibility-proof-lite
python3 - <<'PY'
import hashlib, json, pathlib, urllib.request
base = pathlib.Path('packages/eligibility-proof-lite')
for item in json.loads((base / 'fixtures/sources.json').read_text())['files']:
    path = base / item['path']
    if path.exists():
        data = path.read_bytes()
    elif 'url' in item:
        data = urllib.request.urlopen(item['url'], timeout=60).read()
    else:
        raise SystemExit(f'Missing tracked fixture: {path}')
    if hashlib.sha256(data).hexdigest() != item['sha256']:
        raise SystemExit(f'Hash mismatch: {path}')
    if not path.exists():
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_bytes(data)
PY
npm test --prefix packages/eligibility-proof-lite
cargo +1.98.1 test --manifest-path packages/eligibility-proof-lite/rust/Cargo.toml --locked
```

The known-failing execution gate needs the existing pinned RISC0 tools on the command path. It builds release guests with locked dependencies and runs a debug host. It does not generate a LEZ receipt:

```sh
PATH="$HOME/.cargo/bin:$PATH" RISC0_BUILD_LOCKED=1 cargo +1.98.1 test --manifest-path packages/eligibility-proof-lite/rust/execution/Cargo.toml --locked -- --nocapture
```

`npm run benchmark --prefix packages/eligibility-proof-lite -- --members 3 --attempts 1` records a new small measurement under ignored `results/`. Each proof child has a two-minute timeout. Do not regenerate the tracked fixtures with `--fixtures`: the guest embeds their expected public inputs. Do not run the 100,000-member stage until the verifier gate is resolved and reviewed.

## Limits

The signed transaction fixture is fee-exempt but explicitly uses the charged public action budget of 10,000,000 cycles. It does not test fee settlement or block admission. The separate 33,554,432-cycle fallback for other execution paths was not used to bypass this gate. A complete sale needs additional cycle headroom.

The checker pins one official verification key. Its public-input policy in the guest is fixed to this synthetic fixture, not read from a production sale. It rejects changed inputs and malformed fields/points. Cryptographic verification alone accepts replay; sale state must prevent a second allowance use.

Semaphore proves control of its own identity secret, not an approved LEZ account. This experiment does not establish approved-account binding, duplicate-credential invariance, shared public/private allowances, funded-trade rollback or confidentiality. The common cap and real purchase encoding are not implemented. Current compatibility tokens lack private holdings. A small eligibility proof also does not replace LEZ's native private-transaction proof.

Only public proof values and the public verification key are tracked. The member secret and full witness are not saved. Artifact hashes identify the downloaded bytes; they do not independently establish ceremony security. The unchanged circuit relies on upstream Groth16 setup. A modified account-binding circuit needs separate setup and security review.

The pinned Node dependency tree reports 9 high and 4 moderate audit findings, including nested older snarkjs and ethers/ws dependencies. Actual proving uses the direct snarkjs 0.7.5 pin. No automatic fixes or overrides were applied. This package is research only; its dependencies are not approved for a production wallet.
