# Domain docs

Use one root `CONTEXT.md` and `docs/adr/` for now.

Before exploring, read the context and relevant ADRs. If `CONTEXT-MAP.md` is introduced, follow it to relevant contexts. If domain docs are absent, continue without creating them automatically.

Use the defined terms. Keep curve and LBP meanings separate. Flag ADR conflicts rather than silently changing decisions. Check status: an internal design marked `To be reviewed by Logos team` is not an approved external commitment. Reviewed PoC sources are evidence unless an ADR explicitly adopts a decision. Public documentation must not cite private tickets.
