# Issue tracker

Use Linear team `logos` and project `logos-launchpads`. Resolve identifiers through the connected tools rather than recording them in repository documents. Issues use the `LOG-<number>` format.

Read the issue, comments, linked documents, dependencies and acceptance criteria before work. Later decisions can supersede descriptions; flag conflicts and pending approval.

Do not create duplicate GitHub or local issues. If Linear is unavailable, report the blocker. Get approval before changing remote records unless the user has already requested that action.
